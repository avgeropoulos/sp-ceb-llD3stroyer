# Thermopylae music: MIDI cue to seamless Ogg Opus loop

The three music cues the game asks for with `setMusic('title' | 'battle' | 'lastStand')` are scored
as MIDI, rendered offline with the GeneralUser GS SoundFont, mastered to one common loudness and
shipped as seamless Ogg Opus loops in `src/main/assets/game/audio/music/`. The procedural music in
`js/audio/loops.js` stays as the fallback; the ambience beds stay procedural.

| file | what it is |
|---|---|
| `setup.sh` | once: fetches the pinned npm tarballs (SoundFont, synth, MIDI writer) and a numpy/scipy venv into a cache outside the repo, and checks their hashes |
| `render.mjs` | stage 1: cue MIDI -> seamless 48 kHz stereo float WAV loop (spessasynth_core + GeneralUser GS); also `--check`, `--reference`, `--bank` |
| `master.py` | stage 2: bus EQ, glue compression, true-peak limiting, loudness normalization, Opus encoding as a seamless loop, checks on the decoded file; regenerates `js/audio/musicbank.js` |
| `qa.py` | stage 3: measures what ships (the decoded .ogg): length, loudness, peaks, crest, spectrum, stereo, seam, fatigue proxies; `--browser` adds a Chromium decode check |
| `webcheck.mjs` | the Chromium (Playwright) decoder behind `qa.py --browser` |
| `musiclib.py` | DSP shared by master.py and qa.py: loop-aware filters, BS.1770 loudness, true peak, limiter, seam metrics, an Ogg Opus muxer |
| `cues.json` | the cue names and the brief each one is checked against (loop length range, bpm range, contrast) |

Nothing rendered is committed except the final `audio/music/<cue>.ogg` files and
`js/audio/musicbank.js`. The SoundFont, the npm packages, the venv, WAVs and reports live in
`$THERMOPYLAE_MUSIC_CACHE` (default `~/.cache/thermopylae-music`).

## Rebuilding a cue

```sh
spartan/tools/music/setup.sh                        # once (about 30 MB of tarballs + a venv); --verify re-checks the cache
C=${THERMOPYLAE_MUSIC_CACHE:-~/.cache/thermopylae-music}
node spartan/tools/music/render.mjs --check battle.mid          # validate the loop marking, print the plan
node spartan/tools/music/render.mjs battle.mid                  # -> $C/build/battle.loop.wav + battle.render.json
$C/venv/bin/python -I spartan/tools/music/master.py $C/build/battle.loop.wav
                                                    # -> audio/music/battle.ogg, js/audio/musicbank.js, $C/build/battle.master.{wav,json}
$C/venv/bin/python -I spartan/tools/music/qa.py --browser       # QA every cue in audio/music; exit 1 on a FAIL
```

`render.mjs` takes several MIDI files at once; the sidecar JSON next to each is found by name
(`--json` names one explicitly, so use it with one MIDI). `master.py --out-dir DIR --bank-out FILE`
and `qa.py --music-dir DIR` work on a scratch directory instead of the game (`master.py` only
rewrites the game's `musicbank.js` when it writes into the game's `audio/music`). Times on 4 CPU
threads for a 2-minute loop: render about 30 s, master 1-2 min, QA with `--browser` about 50 s a cue.

`render.mjs --bank` regenerates `musicbank.js` from the `.ogg` files on disk (their `LOOPLENGTH`,
`BPM` and `LUFS` tags), so the bank always matches what ships:

```js
// GENERATED by spartan/tools/music/render.mjs. Do not edit by hand.
/** Pre-rendered music cues: seamless Ogg Opus loops. */
export const MUSICBANK = Object.freeze({
  title: Object.freeze({ file: 'audio/music/title.ogg', dur: 90.0, bpm: 64, lufs: -16.0 }),
  ...
});
```

`file` is relative to the game root (`src/main/assets/game`), `dur` is the exact loop length in
seconds (samples / 48000, to the microsecond), `bpm` the nominal tempo, `lufs` the integrated loudness.

## The loop convention (for composers)

1. **One Standard MIDI File per cue**, named after the cue (`title.mid`, `battle.mid`,
   `lastStand.mid`): format 0 or 1, one port, channels 1-16 (channel 10 is drums; program 48 on it
   selects the GS Orchestra kit). Any PPQ, tempo map and time signatures.
2. **Mark the loop body** `[loopStart, loopEnd)` with a sidecar JSON of the same name
   (`battle.json`), either in seconds or in 1-based bar numbers (end exclusive):
   ```json
   { "cue": "battle", "bpm": 100, "bars": 48, "loopStartSeconds": 115.2, "loopEndSeconds": 230.4 }
   { "cue": "battle", "bpm": 100, "loopStartBar": 49, "loopEndBar": 97 }
   ```
   If both forms are given they must agree; `bars`, if given, must match. Other keys are ignored.
   Without a sidecar, MIDI marker (or text/cue-point) events named `loopStart` and `loopEnd` are used.
3. **Both ends sit on bar lines** of the MIDI's own time signatures (the body is a whole number
   of bars; an off-bar marking is refused unless `--allow-offbar`).
4. **The loop length is a whole number of 20 ms** (960 samples): bars x quarter notes per bar x
   60 / bpm must be a multiple of 0.02 s. Then the Opus stream loops on a codec frame boundary (see
   below) and the loop is also a whole number of samples at 44.1 kHz. `render.mjs` warns
   otherwise and `master.py` falls back to a mode with a faint codec-noise splice at the wrap.
   Tempos that always work: 60, 75, 80 (4/4), 96 (4/4), 100, 120. Others need a bar count that is
   a multiple of: 64 bpm 4/4: 2, 3/4: 8; 72 bpm 4/4: 3; 90 bpm 4/4: 3; 84 or 105 bpm: 7; 108 bpm
   4/4: 9, 3/4: 3; 66, 88 or 110 bpm: 11. A MIDI tempo is whole microseconds per quarter (72 bpm is
   833333 us, so 12 bars last 39.99998 s); with one tempo in the body the renderer uses the nominal
   length (bars x beats x 60 / bpm) when it is within 5 ms of the MIDI's.
5. **Everything before loopStart is a pre-roll, played once**: the GS reset SysEx, program changes,
   bank selects, volume/pan/expression, reverb (CC91) and chorus (CC93) sends, pitch-bend range RPNs.
   It may also hold the whole body written out once as a warm-up (the composers' `lib.mjs` does
   this); one bar of setup is enough, because the renderer warms up by itself.
6. **The body is every event in [loopStart, loopEnd).** A note that starts in the body keeps its
   own note-off even past loopEnd: it rings across the seam into bar 1, as written. Other events at
   or after loopEnd are ignored (reported). If a controller or the pitch wheel moves during the
   body, set the value bar 1 needs on the loopStart tick; `render.mjs` lists the controllers whose
   value changes across the seam (`seamControllerChanges`).
7. **Do not** put all-notes-off, reset-all-controllers or a GS reset inside the body (they would
   cut the notes ringing across the seam), leave a note without its note-off, or rely on events
   after loopEnd. SysEx exactly on the loopStart tick is treated as setup.
8. **Level**: write the dynamics you want inside the cue; `master.py` sets the absolute level
   (-16 LUFS). Keep the raw render's peak around 0 dBFS or below (`peakDbfs` in the render report);
   anything over +12 dBFS is reported.

What `render.mjs` does with that: it plays the pre-roll, then the body three times back to back
(the body's event offsets are rounded to samples once and reused, so every pass is scheduled
identically, sample-exact), and keeps pass 2: its start already holds pass 1's ring-out (reverb,
releases, notes crossing the seam), so the cut loops without a seam. Pass 3 is the proof: the
samples after the cut's end in the continuous render must equal the cut's own start
(`seam.maxDiffVsPeakDb`, typically -125 to -145 dB; a warning above -60). The two free-running
modulators in spessasynth's master effects (the chorus LFO and the Dattorro reverb's tank
excursion) are phase-locked to the loop with a whole number of cycles per loop (a rate change well
under 1 %); every other modulator runs per voice from its note-on, so the render is periodic.

## Mastering (master.py)

Every stage treats the signal as a loop (filters are applied circularly in the frequency domain,
the compressor and limiter warm up on the loop's own tail), so mastering cannot create a seam.

1. **Bus EQ**: an 8th-order Butterworth high-pass at 35 Hz (-11 dB at 30 Hz, -23 dB at 25 Hz,
   -0.3 dB at the contrabass's low E, 41 Hz) and a broad 300 Hz dip of 1-3 dB sized by how far
   200-400 Hz stands above the spectrum's own trend (stacked low strings, choir and drones).
2. **Glue**: a stereo-linked 2:1 RMS bus compressor (30 ms attack, 300 ms release, side-chain
   high-passed at 90 Hz so timpani do not pump), about 2 dB of gain reduction on the loudest passages.
3. **Loudness and true peak**: gain plus a look-ahead true-peak limiter (4x oversampled), iterated
   until the integrated loudness (BS.1770-4) is -16.0 LUFS and the *decoded Opus file* stays under
   -1.5 dBTP (the codec adds 0.2-0.4 dB of overshoot, so the limiter ceiling is lowered by that much).
4. **Opus** (libopus via ffmpeg, about 80 kb/s VBR, 20 ms frames, stereo, no phase-inverted
   intensity stereo because phone speakers sum to mono), **looped in the packet domain**: the
   encoder is fed [pad | loop | loop | loop head], the pad sized so its frame grid starts exactly on
   the loop; pass 1 warms the encoder up and pass 2's packets are the loop. The file holds pass 2's
   last 50 packets followed by all of pass 2's packets, and the Ogg pre-skip hides the copies. The
   decoder therefore enters bar 1 in the state in which it leaves the last bar: the wrap is an
   ordinary Opus frame boundary, and the decoded wrap is checked to equal (to the bit, in practice)
   a continuous decode across the end of pass 2. Without this, the codec noise either side of the
   wrap would come from frames encoded a minute apart and splice into a faint tick. A loop that is
   not a multiple of 960 samples falls back to circular priming ([loop tail | loop | loop head], the
   pre-skip hides the tail, the final granule position trims the end): still sample-exact, with that splice.
5. **Checks on the decoded file** (ffmpeg): the length is exactly the loop length, no lag, the seam
   (below), the true peak, the loudness. Any failure exits with status 1.

**Loudness target.** `render.mjs --reference` renders the procedural cues from `js/audio/loops.js`
(imported read-only) and `master.py --measure-reference DIR` measures them as the game plays them
(the mono loop up-mixed to L = R): title -16.4, battle -16.0, lastStand -20.8 LUFS (ffmpeg's
ebur128 agrees within 0.2 LU). The new cues all sit at -16.0 LUFS, the title/battle level (their
power mean, -16.2, on the 0.5 LU grid), so the swap keeps the music bus's balance against speech and
SFX; lastStand comes up 4.8 LU because the three cues share one level. The game ducks music under
speech; music at this level with a PLR around 14 dB leaves the SFX their transients.

## Seam metrics

`musiclib.seam_metrics` compares the wrap (last sample to first) with the rest of the loop:
`jump_local` / `curv_local` (the step and second difference across the wrap over the largest within
5 ms: about 1 or less is seamless; a cutting error measured x7-x60), `lpc_ratio` (a 32-pole linear
predictor whitens the music, a click is an unpredictable spike: the error within 1 ms of the wrap
over the median per-ms maximum, vs. the same at the other bar lines), `hf_db` (energy above 6 kHz in
the 1 ms at the wrap vs. its 250 ms neighbourhood and vs. the bar lines), `flux_vs_barlines`
(spectral flux at the wrap vs. the other downbeats: a downbeat at the loop start is music, not a
click), `level_db` (20 ms after vs. before, vs. the bar lines). Calibration on test loops: a good
loop reads jump 0.1-0.5, curvature 0.4-0.6, lpc 0.6-1.1; dropping 48 samples (a 1 ms cut error)
reads jump 9-13, curvature 32-60, lpc 38-46; a loop cut from the first pass (no ring-in) 7 / 34 /
37. With the old circular-priming Opus encoding the decoded wrap read lpc 5-10 (the codec-noise
splice); the packet loop reads 0.7-1.0.

## QA (qa.py)

Per cue, from the decoded .ogg: duration (vs. the `LOOPLENGTH` tag, the bank's `dur` within 1 ms,
the brief); integrated loudness, LRA, max momentary/short-term, PLR; true peak, sample peak,
clipped samples, flat-topped runs; crest factor (whole loop, median of 400 ms windows); spectral
centroid, 85 % roll-off, spread, and energy shares from the loop's exact periodogram (under 35 Hz,
under 120 Hz = the low-end ratio, 200-400 Hz mud, the 200 Hz-3.5 kHz speech band, presence, air);
stereo correlation (whole loop and 5th percentile of 400 ms windows), side/mid ratio and the
loudness change when summed to mono; the seam metrics and verdict. The **fatigue proxies** use
8-bar windows: loudness, centroid, onset density and speech-band level per window, their spread
(sections that all sound alike tire the ear over 20 minutes), the breath depth (loudest vs.
quietest 4 bars, checked against `contrastLU` in cues.json), the share of the loop within 3 LU of
its loudest short-term level ("no breath"), and the quietest window's speech-band level (room for
Leonidas' voice). FAIL: wrong length, a click, true peak over -1.0 dBTP, clipping, loudness more
than 0.5 LU off target or off the bank, out-of-phase stereo. WARN: everything a person should judge
by ear. The pipeline cannot listen: these numbers catch broken files and flag suspicious mixes,
they do not replace a listen on a phone speaker and on headphones.

## Notes for the game (Chromium / Android WebView)

Checked with `qa.py --browser` (headless Chromium 141, the WebView's engine):

* `decodeAudioData` honours the Ogg Opus pre-skip and end trim: in a **48 kHz** context the buffer
  is exactly `round(dur * 48000)` samples and loops seamlessly with `source.loop = true`.
* In a **44.1 kHz** context `decodeAudioData` resamples the loop as a one-shot, edges padded with
  silence: the buffer can come out a sample short, and the wrap carries the resampler's edge (a faint
  click: on the test cues a prediction-error spike of x8-35 and an HF burst of up to 26 dB at the
  wrap, against x1 at a clean wrap). So decode the music with a 48 kHz `OfflineAudioContext`
  (`new OfflineAudioContext(2, 1, 48000).decodeAudioData(bytes)`; AudioBuffers are not tied to a
  context) and play that buffer in the game's context, whatever its rate: an
  `AudioBufferSourceNode` resamples a 48 kHz buffer while it plays and wraps cleanly (x0.4-1.4 at
  the wrap). Android devices mostly run WebAudio at 48 kHz, but not all.
* Loop the whole buffer (`loopStart`/`loopEnd` unset). If a WebView ever returns a longer buffer,
  `loopEnd = dur` restores the loop.

## Reproducibility

`setup.sh` pins every input: npm tarballs by sha512 integrity (generaluser@1.47.1,
spessasynth_core@4.3.22, stb-vorbis@0.0.6, midi-writer-js@3.2.1 and its @tonaljs dependencies),
GeneralUser.sf2 by sha256 (`f45b6b4a...b839a`, checked again by `render.mjs` before every render),
numpy 2.5.4 and scipy 1.18.1 as wheels. Nothing from the npm packages is run at install time (`npm
pack` downloads, `tar` unpacks). `render.mjs` refuses another spessasynth_core version, because its
effect phase locks patch that version's chorus and reverb (it checks their shape at run time too).
Renders are deterministic: the same MIDI gives the same WAV, bit for bit. The Opus stream depends on
the ffmpeg/libopus build (ffmpeg 6.1.1 here); the checks in `master.py` hold for any build.
